# CLAUDE.md — gvannoorden.github.io

## What this is

Gavin's personal splash page, served by GitHub Pages at
https://gvannoorden.github.io. It links out to his Notion site and to each
hosted project.

Local folder name matches the repo name because GitHub requires that exact name
for a user Pages site — this is the one place the `personal-` prefix convention
in the global CLAUDE.md does not apply.

## Constraints

- **One page, no build step.** `index.html` plus `assets/*.webp` is the whole
  site. No npm, no bundler, no framework. If a change needs one, it's the wrong
  change. (`tools/` is an optional utility, not a build step — see below.)
- CSS and JS stay inline. The only external requests are Google Fonts and the
  local `assets/` images; the favicon is a data URI.
- **No links to github.com.** Gavin took them out deliberately — the page shows
  the apps, not their source. The `gvannoorden.github.io/<app>/` URLs are the
  apps' own hosts and are fine.
- Respect `prefers-reduced-motion` — the mote canvas and the turning sigil rings
  must both switch off.
- High-fantasy typography without tipping into costume: Cinzel Decorative for
  the name, Cinzel for headings and small caps, EB Garamond for body.

## Theming

Dark is the base palette on `:root`; light is a warm parchment set. The light
block is **written twice on purpose** — once under
`@media (prefers-color-scheme:light)` scoped to `:root:not([data-theme="dark"])`,
once under `:root[data-theme="light"]` — so that the system default and an
explicit toggle both win in both directions. **Keep the two copies in sync.**

Nothing outside those blocks may hardcode a colour; use the tokens. `--verdant`
is the green, `--gold` the ornament accent, `--head` display headings,
`--mithril` body text, `--muted` / `--muted-dim` the two quieter greys. The
theme-dependent effects also live in tokens: `--wash`, `--veil`, `--glow`,
`--grain-blend`, `--card-shadow`, `--shot-veil`, and `--mote-green` /
`--mote-gold` (read by the canvas script, which re-reads them on toggle).

Three theme states: no `data-theme` attribute means follow the system;
`light` / `dark` are explicit and persisted to `localStorage`. An inline script
in `<head>` applies the saved value before first paint so there's no flash.

## The wordmark

The surname in the `<h1>` is Gavin's Scott-Miller logo (Silverstone typeface),
not type. `assets/scott-miller.svg` was cut from his master artwork: the
"Goods & Services" subtitle removed, the viewBox tightened to the measured
bbox of what's left. **The rule under the name and the long hyphen are part of
the artwork** — they're separate clipped shapes, not text decoration, so don't
try to reproduce them in CSS.

It's applied as a CSS `mask` on `h1 .mark` with `background-color:var(--verdant)`,
so one monochrome file takes the theme colour. Under `@supports` failure the
typeset `.mark-txt` fallback shows instead; that span also stays in the DOM
(visually hidden) so the name is still readable to screen readers.

## The sigil

The leaf lives in three places, and they are separate copies of the same
geometry — change one, change all three:

1. inline in `index.html` (uses the theme tokens, so it recolours)
2. the favicon data URI in `<head>`
3. `assets/sigil-triangle.svg` / `assets/sigil-leaf.svg`, standalone artwork
   with literal colours, plus 1024px transparent PNGs beside them

Two traps in the standalone files:
- **No `--` inside an XML comment.** A standalone `.svg` is parsed as strict
  XML, so a comment mentioning `var(‑‑something)` makes the whole file fail to
  load as an `<img>` — silently, with no console error. Reword instead.
- Stroke widths on the scaled leaf are pre-divided by the scale factor.
  `vector-effect="non-scaling-stroke"` looks equivalent at small sizes but pins
  strokes to screen pixels, so the leaf goes hairline when shown large.

## The works grid

Eight cards: the first and the last three carry `.work--feature` and span the
full width (image and body going side-by-side above 900px), the middle four
form a 2×2. The grid is two columns, so the count of non-feature cards has to
stay even — that's the thing that breaks when a project is added. **If the
project count changes, revisit both rules** under `/* WORKS */` and which cards
are features.

The last three cards are all features and sit stacked, so the middle one
carries `.work--flip` (`row-reverse`) — otherwise they read as one block
repeated. A sibling selector can only flip every feature after the first, so
the flip is an explicit class.

Each card is a single `<a>` wrapping the whole thing, so the `href` appears once.

## Screenshots

`assets/<name>.webp`, 1280×800, regenerated by
`node tools/refresh-shots.mjs [name…]`. It drives headless Edge over CDP.

Two things that cost time, so don't re-derive them:
- `--virtual-time-budget` starves real network requests, so MapLibre tiles and
  the terrain render never arrive. Use real time and wait on the app's own
  signals (`map.once('idle')`) instead.
- macOS `sips` reads WebP but cannot write it, and there's no cwebp or
  ImageMagick on this machine. The script encodes in a page's `<canvas>` via
  `toDataURL('image/webp')`, served from a real http origin so the image isn't
  blocked and the canvas isn't tainted.

The hymns thumbnail is a public Notion page rather than an app, which brings
two extra needs, both handled by its `APPS` entry: `dark: true`, because
headless Chromium reports `prefers-color-scheme: light` and Notion obeys it, so
the shot otherwise comes back white; and a `drive` that scrolls
`.notion-scroller` — Notion scrolls an inner div, not the window, so
`window.scrollBy` does nothing.

Genealotree and the shortcut tracker are password-gated, so their thumbnails
default to the front door. Don't try to get past those gates. To use an interior
view, drop the PNG at `.shots/<name>.png` and run
`node tools/refresh-shots.mjs <name> --no-capture`, which skips the browser and
only crops + encodes. A full-window UI shot wants `crop: [0, 0, 1, 1]`; the
centred-card crops in `APPS` are tuned for the login screens.

## Deploying

Push to `main`. Pages serves from the branch root; there is no workflow. Give it
a minute, then hard-refresh.
